# 카페 재고관리 · 씨앤비 월/목 발주 자동 계산

손으로 적던 **씨앤비 재고조사 시트 3장**(과일청·주스 / 커피·시럽·티 / 브런치)을 그대로 옮긴
모바일 웹앱입니다. 현재 남은 수량만 입력하면 기준 수량(시트의 빨간 숫자)과 박스 규칙을 적용해
**발주 수량을 자동 계산**하고, 카카오톡으로 바로 보낼 수 있는 발주 문자를 만들어 줍니다.

설치나 서버가 필요 없습니다. 브라우저에서 열면 바로 동작하고, 홈 화면에 추가하면 앱처럼 쓸 수 있습니다.
직원 여러 명이 같은 재고조사를 동시에 보려면 [직원과 실시간 공유하기](#직원과-실시간-공유하기)를 보세요.

## 주요 기능

두 장부로 나뉩니다. **제품(재료)** 은 월·목 발주 시트 3장, **자재(소모품)** 는 수요일 재고조사 시트(포장·컵·봉투·위생용품, 지하창고 기준)입니다. 재고조사·발주 탭 위의 전환 버튼으로 오갑니다. 장부마다 초안·발주일·발주 문자가 따로 있습니다.

| 탭 | 기능 |
| --- | --- |
| 📋 재고조사 | 종이 시트처럼 한 줄에 "이름 · 빨간 기준 · 검은 숫자"가 같은 자리에 정렬됩니다. 수량을 넣으면 기준 숫자 아래에 `발주 1박스`처럼 시킬 양이 바로 뜨고, 위의 분류 칩으로 진행을 보며 건너뜁니다. 숫자 칸을 누른 줄에만 `0`/`예상`/`기준`/`지움` 버튼과 상세 규칙이 펼쳐지고, 사진 입력·예상값 채우기·전부 지우기·크게 보기는 `⋯` 메뉴에 있습니다. 입력은 자동 저장됩니다. |
| 📷 사진 자동 입력 | 손글씨 시트 사진이나 선반 실물 사진을 찍으면 Claude 비전 모델이 수량을 읽어 채워 줍니다. (Anthropic API 키 필요, 선택 기능) |
| 🧾 발주 | `기준 − 현재`로 부족분을 계산하고 박스 단위 올림, 최소 발주, 재발주점 규칙(유자청·청귤청)을 적용합니다. 수량을 직접 고칠 수 있고, 발주 문자를 복사/공유합니다. |
| 📈 기록 | 확정한 재고조사·발주 이력, 품목별 소비 속도, 자주 품절되는 품목, 기준 수량 변경 제안. |
| 🏷️ 품목 | 품목 추가/편집/숨김, 기준 수량, 1박스 개수, 발주 단위, 최소 발주, 재발주점 규칙, 사진 인식용 별칭. |
| ⚙️ 설정 | 공유 저장소(직원과 실시간 공유), 매장·담당자 이름, 발주 요일, API 키, JSON 백업/복원. |

## 바로 쓰기

### 1) GitHub Pages로 배포 (권장)

1. 저장소 **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 바꿉니다.
2. 기본 브랜치(`main`)에 push하면 `.github/workflows/pages.yml`이 자동으로 배포합니다.
3. `https://<계정>.github.io/auto_cafe_object_count/` 를 휴대폰에서 열고 **홈 화면에 추가**하세요.

### 2) 로컬에서 열기

```bash
npm install
npm run serve      # http://localhost:8080
```

### 3) 파일 하나로 배포하기

```bash
npm run build      # dist/cafe-inventory.html (모든 코드·스타일이 들어 있는 단일 HTML)
```

`dist/cafe-inventory.html` 하나만 어디에 올리거나 메신저로 보내도 동작합니다.
`dist/artifact.html`은 claude.ai 아티팩트용 조각으로, 아티팩트 안에서는 API 키 없이
뷰어의 Claude 계정으로 사진 인식이 됩니다 (`claude.use("sample")`).

## 발주 수량 계산 규칙

`src/logic/order.js` 에 있는 순수 함수이며 단위 테스트로 검증됩니다.

| 상황 | 계산 |
| --- | --- |
| 일반 품목 | `발주 = max(0, 기준 − 현재)` |
| 박스 발주 품목 (`1box>6` 표기) | 부족 개수를 박스로 올림: `ceil(부족 / 6)` 박스 |
| 기준이 박스 단위 (`2BOX`) | 박스 단위로 세고 박스 단위로 발주 |
| 세는 단위가 박스인 품목 | 입력한 박스 수 × 1박스 개수로 환산해 계산 (1박스 개수가 없으면 계산하지 않고 경고) |
| 최소 발주 수량 | 부족분이 있으면 최소 수량 이상으로 |
| 재발주점 규칙 (유자청·청귤청) | 시트 각주 "3개 미만일 때 1박스씩" → 현재 < 3 이면 1박스, 아니면 0 |
| 미입력 품목 | 발주 0으로 두고 발주 탭에 경고 표시 |

계산 결과는 발주 탭에서 품목별로 직접 고칠 수 있으며, 고친 값은 노란 테두리로 표시됩니다.
재고조사 탭에서 그 품목의 수량을 다시 고치면 직접 고친 발주 수량은 지워지고 다시 자동 계산됩니다.

## 시트 → 데이터 옮긴 내용

`src/data/items.js` 가 시드 데이터입니다. 사진 3장을 독립적으로 두 번 판독하고 대조해 옮겼습니다.

- 빨간 숫자 → `par`(기준 수량), 흰 스티커로 고친 값(유자청 8, 청귤청 8, 블루베리청 6, 아이스크림 3)은 스티커 값을 사용
- `(1box>6)` → `boxSize: 6`, 박스 발주
- `배도라지차 2BOX` → 박스 단위로 세고 발주
- 각주 `* 유자, 청귤 최소발주 6○○ / 3개 미만일 때 1 BOX씩` → 재발주점 규칙 (각주 사진이 흐려 "6" 뒤 단위는 확인 필요)
- 손글씨로 추가된 라면류(신라면·진라면·너구리·삼양라면·짜파게티)와 단무지는 기준 수량 없이 등록
- 줄을 그어 지운 `컵라면`은 "사용 안 함"으로 등록
- **시트 1의 `레몬`(주스 칸, 기준 1)과 시트 2의 `레몬`(시럽 칸, 기준 6)** 은 이름이 같아 `레몬(과일 · 1장 주스 칸)` / `레몬(과일)`로 구분했습니다 (사용자 확인: 레몬은 시럽이 아닌 진짜 과일). 같은 레몬이면 품목 탭에서 하나로 정리하세요. 같은 확인으로 `자몽시럽` · `청포도시럽`(시럽), `달콤사과`(병 주스)로 적었습니다.
- 그룹(과일청, 주스, 티 …)은 시트에 없는 앱의 분류입니다. `디카페인콜드브루`는 원두·우유 그룹에 두었습니다.
- 자재 시트(`src/data/supplies.js`, 씨앤비 재고조사 수요일): 빨간 숫자 → `par`, "2묶음"·"1.5묶음" → `par` 2 / 1.5 + `unitName: '묶음'`, "각 2"(라텍스장갑)·"베이커리확인"(유산지)·빈칸(컵캐리어)은 메모로 남기고, 손글씨로 추가된 품목(종이봉투·빵 스티커·나무젓가락·라면용기 등)은 기준 없이 등록했습니다. 기준이 1.5처럼 소수여도 발주 수량은 정수로 올립니다.

기준 수량은 언제든 품목 탭에서 바꿀 수 있고, "품목을 기본 시트 데이터로 되돌리기"로 원복할 수 있습니다.

## 사진 자동 입력 (AI)

claude.ai 아티팩트로 열었다면 설정 없이 바로 됩니다(처음 한 번 "이 페이지가 Claude를 사용"하도록 허용).
GitHub Pages나 로컬에서 쓰려면 API 키가 필요합니다.

1. [Anthropic Console](https://console.anthropic.com/)에서 API 키를 만듭니다.
2. 설정 탭 → **Anthropic API 키**에 붙여 넣습니다. 키는 이 기기의 브라우저(localStorage)에만 저장됩니다.
3. 재고조사 탭 → **📷 사진으로 자동 입력** → 시트 사진(손글씨 숫자 읽기) 또는 선반 사진(개수 세기) 선택 → 인식 결과를 확인하고 적용.

- 모델: `claude-opus-5`, 구조화 출력(JSON schema)으로 품목·수량·단위·확신도를 받습니다.
- 안전 분류기가 요청을 거절하면 서버에서 자동으로 대체 모델로 재시도합니다(`fallbacks: "default"`). 원치 않으면 `src/ai/extract.js`에서 `betas`/`fallbacks` 두 줄을 지우세요.
- 인식된 이름은 등록 품목과 유사도 매칭(`src/logic/match.js`)되며, 확신도가 낮은 항목은 체크가 해제된 채로 나옵니다.
- 명령줄에서도 같은 프롬프트로 시험할 수 있습니다.

```bash
ANTHROPIC_API_KEY=sk-ant-... node scripts/extract-from-photo.mjs --mode sheet 사진1.jpg 사진2.jpg
```

## 데이터 보관과 공유

- 기본적으로 모든 데이터는 **이 기기의 브라우저에만** 저장됩니다(localStorage). 서버로 전송되지 않습니다.
- 여러 직원이 같은 데이터를 실시간으로 보려면 **공유 저장소**를 켭니다 → [직원과 실시간 공유하기](#직원과-실시간-공유하기). 켜면 이 기기에 저장하면서 공유 저장소에도 같이 올라갑니다.
- 공유 없이 기기만 옮길 때는 설정 → **백업 내보내기(JSON)** → 상대 기기에서 **백업 불러오기**. 백업 파일에 API 키는 들어가지 않고, 불러오기 직전 상태는 한 벌 보관되어 "불러오기 전 상태로" 되돌릴 수 있습니다.
- 홈 화면 앱과 브라우저 탭을 동시에 열어도 한쪽에서 저장한 내용이 다른 쪽에 반영됩니다.

## 직원과 실시간 공유하기

기본값은 "이 기기만"입니다. 상단 바의 작은 알약(**이 기기만 / 연결 중 / 공유 중 / 연결 안 됨**)이 지금 상태이고, 누르면 설정 탭의 **공유 저장소** 카드로 갑니다. 공유를 켜는 길은 두 가지입니다.

### (a) 빠른 길 — claude.ai 아티팩트 링크

이 앱을 claude.ai 아티팩트로 열었다면(`dist/artifact.html`) 아무 설정 없이 **같은 Claude 계정(조직)으로 로그인한 기기끼리** 자동으로 공유됩니다(아티팩트 db). 사장님 휴대폰과 매장 태블릿이 같은 계정으로 로그인되어 있으면 바로 같은 재고조사를 봅니다.

한계: 그 계정(조직) 밖의 사람과는 공유할 수 없습니다. 직원 각자의 휴대폰까지 공유하려면 아래 (b)로 가세요.

### (b) 직원 모두 — GitHub Pages + Firebase

GitHub Pages 주소로 앱을 배포하고, 데이터는 Google Firebase(Firestore)에 둡니다. 링크가 있는 사람은 누구나 같은 데이터를 실시간으로 봅니다. 처음 한 번 15분쯤 걸리고 비용은 없습니다.

1. [console.firebase.google.com](https://console.firebase.google.com) 에 Google 계정으로 로그인 → **프로젝트 추가** (이름은 아무거나, **Google 애널리틱스는 끄기**).
2. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기** → 위치 `asia-northeast3 (서울)` → **프로덕션 모드**로 시작.
3. Firestore 화면의 **규칙** 탭에 이 저장소의 [`firestore.rules`](firestore.rules) 내용을 그대로 붙여 넣고 **게시**.
4. 왼쪽 위 **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹(`</>`) 추가** → 앱 닉네임 아무거나(호스팅 체크 안 함) → 등록 → 화면에 나오는 `firebaseConfig = { apiKey: ..., projectId: ..., appId: ... }` 를 복사.
5. `src/data/share-config.js` 를 열어 아래처럼 넣고 커밋/푸시합니다. (먼저 시험해 보려면 설정 탭 → 공유 저장소 카드에 같은 내용을 붙여 넣고 **연결** — 이 기기에서만 적용됩니다. Firebase 콘솔 조각을 그대로 붙여 넣어도 읽습니다.)
   ```js
   export const SHARE_CONFIG = {
     // 4번에서 복사한 값
     firebase: { apiKey: '...', authDomain: '...', projectId: '...', storageBucket: '...', messagingSenderId: '...', appId: '...' },
     // 매장 구분 코드: 무작위 문자열 12자 이상 (영문·숫자·-), 예: cnb-7f3k9q2mzx8v
     storeCode: '...',
   };
   ```
6. GitHub 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**. 푸시하면 자동 배포되어 `https://<계정>.github.io/auto_cafe_object_count/` 주소가 생깁니다. 직원에게 링크를 공유하고 각자 **홈 화면에 추가**하면 끝입니다.

연결되면 상단 알약이 **공유 중**으로 바뀝니다. 설정 탭의 공유 저장소 카드에서 마지막 동기화 시각과 오류 내용을 볼 수 있고, 붙여 넣은 설정은 **공유 끄기**로 지울 수 있습니다.

#### storeCode 는 무엇인가

- Firestore 규칙([`firestore.rules`](firestore.rules))은 `stores/{storeCode}/**` 아래만 읽고 쓰게 허용하고 나머지 경로는 모두 거부합니다. 앱은 그 아래에 품목·재고조사·발주·설정을 저장합니다.
- storeCode 는 앱 페이지(배포된 파일) 안에 들어 있으므로 **링크를 아는 사람은 누구나 그 매장 데이터를 읽고 쓸 수 있습니다.** 로그인 없이 바로 쓸 수 있는 대신 프로토타입 수준의 보호입니다. 코드가 새어 나간 것 같으면 `storeCode` 를 새 무작위 문자열로 바꿔 배포하면 됩니다 (기존 데이터는 백업 내보내기 → 새 코드로 연결한 뒤 불러오기).
- Firebase 웹 설정(`apiKey` 포함)은 비밀이 아닙니다. Google 이 공개 페이지에 넣으라고 만든 값이고, 접근 제한은 Firestore 규칙이 합니다. Anthropic API 키·매출 자료 같은 진짜 비밀은 저장소에 넣지 마세요.

#### 요금 · 오프라인

- Firebase 무료(Spark) 요금제: 저장 1GB, 하루 읽기 50,000회 · 쓰기 20,000회. 카페 한 곳의 재고조사(하루 수백 번 쓰기)는 넉넉히 안에 들어가고, 카드 등록 없이 쓸 수 있습니다.
- 오프라인: 지하 창고처럼 신호가 없는 곳에서도 그대로 세면 됩니다. 변경은 기기에 남고(Firestore 영구 캐시), 다시 연결되면 자동으로 올라갑니다. 다른 기기의 변경도 그때 받습니다.

#### 동시에 쓰면 어떻게 되나 (동기화 방식)

재고조사 수량은 **품목별로 합쳐지므로** 두 사람이 같은 조사를 나눠 세도 서로 지우지 않습니다 (같은 품목을 동시에 고치면 나중 값이 남습니다). 품목·발주·설정은 문서 단위라 **마지막 저장이 이깁니다**. 기기가 처음 연결될 때 공유 저장소가 비어 있으면 그 기기의 데이터를 올리고, 이미 데이터가 있으면 공유 저장소가 기준이 됩니다 (`src/sync/engine.js`). 공유 중에는 백업 불러오기·모든 데이터 초기화·품목 되돌리기가 공유 저장소와 다른 기기에도 그대로 반영되므로 확인 창에 그 안내가 붙습니다. 단, 다른 기기에서 **세는 중인 초안**(수량이 들어 있는 재고조사)은 지워지지 않고 다시 올라옵니다 — 입력을 잃지 않는 쪽을 택했습니다. 처음 연결해 올리는 동안은 알약이 **연결 중**으로 남고, 올리다 만 저장소는 다음 기기가 이어서 채웁니다 (`meta/store` 표시). API 키와 붙여 넣은 공유 설정은 기기마다 따로이며 올라가지 않습니다.

#### 개발 · 테스트용 훅

- `window.__SHARED_BACKEND__ = 'local'` — 페이지 스크립트보다 먼저 넣으면 같은 브라우저의 탭끼리(localStorage) 공유하는 가짜 백엔드를 씁니다. 카드에 "같은 브라우저 탭끼리 (테스트)"로 표시.
- `window.__SHARE_CONFIG__` — 설정 탭에 붙여 넣은 값과 `src/data/share-config.js` 보다 우선하는 설정 객체 (테스트에서 Firestore 에뮬레이터를 가리킬 때, `emulator: { host, port }`).
- `window.__STORAGE_KEY__` — localStorage 키를 바꿔 한 브라우저 컨텍스트가 "다른 기기"처럼 동작하게 합니다.
- `node scripts/e2e-firebase.mjs` — Firestore 에뮬레이터(`firebase emulators:start --only firestore`)를 띄운 뒤 두 기기가 실제로 합쳐지는지 확인하는 스모크 테스트. 평소의 `npm run e2e` 는 공유 없이(이 기기만) 돕니다.

## 판매 자료 분석 (POS × 레시피 → 소비량 · 예상 재고)

POS의 "그룹별 매출분석" 월별 보고서(PDF)와 메뉴 레시피가 있으면, 세지 않고도 재고 품목별 소비 속도를 계산해
재고조사 탭에 **예상 재고**와 **확인 필요** 표시를 띄울 수 있습니다.

```bash
# 1) 보고서 PDF에서 텍스트 추출 (pypdfium2 등) → data/pos/1월.txt … , 레시피 텍스트 → data/pos/recipe.txt
# 2) 레시피 구조화 JSON → data/recipes.json  (scripts/build-recipes.mjs <structured.json>)
node scripts/pos-analysis.mjs        # data/analysis.json, data/consumption.json 생성 + 요약 출력
node scripts/pos-report.mjs          # docs/analysis/index.html 보고서 (매출 금액 없음)
node scripts/make-pdf.mjs docs/analysis/index.html "docs/판매데이터-소비량-분석.pdf"
```

- `data/`(매출 자료·소비 모델)와 생성된 보고서(`docs/analysis/`, PDF)는 **저장소에 올리지 않습니다**(.gitignore). 공개 저장소이기 때문입니다. 보고서는 위 명령으로 언제든 다시 만들 수 있습니다.
- `data/consumption.json`이 있으면 `npm run build`가 단일 파일 빌드에 소비 모델을 심습니다(비공개 배포용). GitHub Pages 배포판에서는 설정 탭 → "소비 모델 불러오기"로 같은 파일을 넣습니다.
- 연결표: `src/data/pos-map.js` (POS 상품명 → 레시피 메뉴·에스프레소 단품·옵션·병음료, 레시피 재료 → 재고 품목 + 1포장 크기). 자료에 없는 값은 **가정하지 않고** `perPackage: null`로 비워 둡니다(원재료 양만 계산, 앱 예상 재고에서는 제외). 보고서 3장의 확인 목록에 답이 오면 그 값을 채우고 다시 돌리면 됩니다.
- 레시피에 수량이 인쇄되지 않은 재료(가니쉬·거품·티백 봉 수 등)는 수량을 지어내지 않고 잔 수(`serving`)로만 집계합니다. 같은 이유로 HOT/ICE 레시피가 없는 메뉴는 "레시피 없음"으로 남깁니다.
- 그래도 계산을 진행하기 위한 **추정값 층**이 `src/data/pos-estimates.js`에 따로 있습니다(1샷 18g, 시럽 밀도 1.3, 티백 1봉 등, 근거 표기). 기본으로 덧씌워 계산하며 해당 품목은 보고서와 앱에 "추정"으로 표시됩니다. `node scripts/pos-analysis.mjs --no-estimates` 로 끄고, 실제 값이 확인되면 `pos-map.js`에 넣고 추정값은 지웁니다.
- 예상 재고 = 마지막 확정 조사값 + 그 뒤 발주 입고 − 소비 속도(그 달) × 경과일. 예상값의 오차 범위 안에서 발주량이 달라지면 "확인 필요"로 표시합니다 (`src/logic/forecast.js`).

```
index.html            앱 셸
src/app.js            상태·렌더링·이벤트 위임
src/store.js          localStorage 저장/마이그레이션/백업

src/data/supplies.js  자재(소모품) 수요일 시트 시드

src/logic/order.js    발주 수량 계산, 발주 문자 생성

src/logic/pos.js      POS 매출 보고서 텍스트 파서
src/logic/consumption.js 판매량 × 레시피 → 재료·품목 소비량
src/logic/forecast.js 예상 재고 · 확인 필요 판정
src/data/pos-map.js   POS 상품 ↔ 레시피 ↔ 재고 품목 연결표
src/ui/*.js           탭별 화면 (count, order, history, items, settings, photo)
src/sync/*.js         공유 저장소 동기화 (engine: 3-way 병합, index: 백엔드 선택, artifact / firebase / local 백엔드)
src/data/share-config.js  배포용 Firebase 공유 설정 (비워 두면 이 기기만)

sw.js                 오프라인 캐시
tests/                node --test 단위 테스트
scripts/e2e.mjs       실제 크로미움 스모크 테스트 + 스크린샷
```

```bash
npm test          # 단위 테스트
npm run e2e       # 브라우저 스모크 테스트 (Playwright, e2e-out/ 에 스크린샷)

```
