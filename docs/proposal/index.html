이 문서를 읽는 방법

바쁘면 1장과 11장만 읽어도 결정할 수 있습니다. 5장은 "자동으로 세는 게 되나"에 대한 답이고, 6장은 "앱 말고 웹으로 직원 모두가 쓸 수 있나"에 대한 답입니다. 기술 용어는 부록에 풀어 두었습니다.

1한 장 요약

무엇을 — 주 2회 재고조사와 씨앤비 발주를 휴대폰 웹앱으로 처리합니다. 앱스토어 앱이 아니라 링크로 여는 웹앱이며, 홈 화면에 추가하면 앱처럼 보이고 오프라인에서도 열립니다.

왜 — 지금은 68개 품목을 매번 세고, 시트에 적고, 머리로 계산해서, 사진을 찍어 보냅니다. 기록이 남지 않아 "얼마나 쓰는지"를 모르고, 담당자 한 명에게 일이 몰립니다.

어떻게 — 세 단계로 갑니다.

"예상 재고"만으로는 부족한 이유와, 그보다 나은 방식
예상 재고는 소비 속도로 "지금쯤 몇 개"를 계산하는 방식입니다. 추정이므로 틀릴 수 있고, 그래서 결국 다 세게 되기 쉽습니다. 제안하는 방식은 예상값이 발주 결정을 바꿀 수 있는 품목만 골라 확인하는 것입니다(5장 3절). 예상값의 오차가 결정에 영향이 없으면 세지 않고, 재발주 경계에 걸린 품목만 확인합니다. 세는 수는 줄이면서 발주 정확도는 지금과 같거나 더 좋아집니다.

결정 요청 — ① 공유 저장소로 Firebase를 쓸지(계정 주체 포함) ② 예외 확인 방식 채택 ③ 사진 인식용 API 키 사용 여부 ④ POS 종류 ⑤ 시트에서 불확실했던 두 가지(레몬 2종, 각주 단위). 자세한 내용은 11장.

2지금의 방식과 문제

지금 하는 일

  1. 월요일·목요일에 코팅된 재고조사 시트 3장을 들고 창고·선반·냉장고를 돌며 68개 품목을 셉니다.
  2. 빨간 기준 숫자(예: 유자청 8)와 남은 수량을 비교해 발주량을 머리로 정하고, 매직으로 적습니다.
  3. 시트를 사진으로 찍어 거래처(씨앤비)나 담당자에게 보냅니다. 다음 조사 때 지우고 다시 적습니다.

불편한 점

문제왜 생기나결과
매번 전부 센다지난번에 몇 개였는지, 얼마나 쓰는지 기록이 없어 매번 처음부터 셉니다.회당 20~30분, 주 2회
계산·전달 실수박스 단위(1box=6), 2BOX, "3개 미만이면 1박스" 같은 규칙을 사람이 기억해 적용합니다.과·소발주, 누락
기록이 사라진다시트를 지우고 다시 쓰므로 소비 추세, 품절 빈도를 알 수 없습니다.기준 수량을 감으로 조정
한 사람에게 몰린다시트와 규칙을 아는 사람만 할 수 있고, 다른 직원은 결과를 볼 수 없습니다.휴무·퇴사 때 공백
사진 공유의 한계손글씨 사진은 검색·집계가 안 되고, 잘못 읽히기도 합니다.거래처와 확인 왕복

시트에서 확인된 규칙

  • 기준 수량은 빨간 인쇄 숫자. 흰 스티커로 고친 값이 있으면 스티커 값(유자청 8, 청귤청 8, 블루베리청 6, 아이스크림 3).
  • (1box>6) 표기 품목(바닐라시럽, 아이스티, 카페시럽)은 1박스 = 6개, 박스로 발주.
  • 배도라지차는 기준이 2BOX, 박스 단위로 셉니다.
  • 각주: "유자, 청귤 최소발주 6○○ / 3개 미만일 때 1 BOX씩". 3개 미만이면 1박스로 옮겼습니다. "6" 뒤 단위는 사진이 흐려 확인이 필요합니다.
  • 손글씨로 추가된 라면류(신라면·진라면·너구리·삼양라면·짜파게티)와 단무지는 기준 수량 없이 등록. 줄을 그어 지운 컵라면은 사용 안 함.
  • 시트 1(주스 칸)과 시트 2(시럽 칸)에 레몬이 각각 있어 "레몬(주스)" / "레몬(시럽)"으로 구분했습니다.

원칙

  • 세는 시간을 줄이되 발주 정확도는 낮추지 않는다. 자동화가 못 미더운 품목은 언제든 직접 센 값이 우선입니다.
  • 직원에게 새 습관을 최소로 요구한다. 필수 습관은 "월·목에 앱 열기"와 "입고 왔을 때 확인 누르기" 두 가지뿐입니다.
  • 설치·계정·비용 없이 시작한다. 링크와 홈 화면 추가만으로 참여합니다.

시트 3장을 그대로 옮긴 웹앱이 완성되어 있습니다. 지금은 각자 휴대폰에만 저장되는 개인용이고, 6장의 공유 저장소를 붙이면 그대로 팀용이 됩니다.

5재고를 세지 않고 알아내는 방법

5.1 완전 자동이 어려운 이유

카페 재고는 카메라나 센서가 보기 어려운 곳에 있습니다. 닫힌 박스 안, 앞 병에 가려진 뒷줄, 지하 창고의 미숫가루, 자몽·레몬·청포도처럼 생김새가 같은 병. 그래서 "기계가 다 세 준다"보다 "사람이 확인해야 할 것만 골라 준다"가 현실적인 목표입니다.

5.2 후보 비교

방법어떻게잘 맞는 품목한계준비
선반 사진 세기 있음선반별 사진을 찍으면 AI가 보이는 개수를 셈앞줄에 한 줄로 보이는 병·팩(시럽, 티, 주스)가려진 것, 닫힌 박스, 비슷한 병. 결과 확인 필요없음
예상 재고지난 조사값 + 입고 − 평균 소비×경과일소비가 일정한 대부분 품목추정이라 틀릴 수 있음. 주말·행사 변동기록 3~4회
예외 확인 제안예상값의 오차가 발주 결정을 바꿀 수 있는 품목만 표시해 실측전 품목예상 재고가 먼저 있어야 함기록 3~4회
입고 확인배송 도착 시 "입고 확인" 한 번. 부족분 표시전 품목안 누르면 예상값이 어긋남습관 1개
개봉 −1새 병을 딸 때 그 품목을 한 번 탭개봉 시점이 분명한 핵심 품목(청, 원두, 우유)직원 전원이 빠짐없이 눌러야 함습관 1개
POS 판매 연동메뉴 판매량 × 레시피 사용량으로 이론 소비량 계산레시피가 정해진 음료 재료POS 내보내기·레시피 표 필요. 폐기·서비스 소비는 못 잡음POS 확인
저울·고정 카메라선반 무게나 매일 자동 촬영대형 매장장비·설치·유지 비용장비

5.3 제안: 예상 재고 + 예외 확인 ("결정 기준 확인법")

발주에 필요한 것은 정확한 개수가 아니라 두 가지 판단입니다. 기준보다 얼마나 부족한가, 그리고 재발주점(예: 3개 미만)을 넘었는가. 예상값에 오차를 붙여도 이 판단이 바뀌지 않으면 세지 않습니다. 판단이 갈리는 품목만 "확인 필요"로 표시합니다.

확인하지 않아도 되는 예 — 탄산수
기준 8. 지난 목요일 5개, 그 뒤 입고 3개, 평균 소비 하루 1.2개(±0.5). 월요일 예상 3.2개 (2~5개). 어느 값이든 3~6개를 발주해야 하고 초안은 5개. 1~2개 차이는 다음 조사에서 자연히 맞춰집니다. → 세지 않음, 5개 발주 초안
확인해야 하는 예 — 유자청
규칙: 3개 미만이면 1박스. 예상 3.4개 (2~5개). 2개면 발주, 3개 이상이면 발주 안 함 — 결정이 갈립니다. → "확인 필요" 표시. 직원은 이 품목만 실제로 봅니다.

정확도를 올리는 장치

  • 요일 구간별 소비 속도. 월→목(평일 3일)과 목→월(주말 포함 4일)을 따로 계산합니다. 지금의 조사 주기가 그대로 학습 데이터가 됩니다.
  • 입고 확인. 발주량이 그대로 들어왔다고 가정하지 않고, 배송 때 "입고 확인"으로 실제 수량을 반영합니다.
  • 오차 자기 점검. 실측할 때마다 예상값과의 차이를 기록해, 오차가 커진 품목은 자동으로 "확인 필요"에 올립니다. 반대로 오차가 작은 품목은 확인 대상에서 빠집니다.
  • 핵심 품목 개봉 기록(선택). 유자청·청귤청·원두·우유·아이스크림처럼 비싸거나 품절이 치명적인 5~6개만 "개봉 −1"을 적용하면 이 품목은 사실상 실시간 재고가 됩니다.

기대 효과와 한계

기록이 3~4주(6~8회) 쌓이면 확인 대상은 68개 중 10~15개 안팎으로 줄어들 것으로 봅니다. 정확한 수는 매장의 소비 변동에 달려 있어 도입 후 측정합니다. 처음 2~3주는 전 품목을 세되, 앱이 예상값을 미리 채워 두므로 "세기"가 "틀린 것만 고치기"로 바뀌어 이 기간에도 시간은 줄어듭니다.

5.4 POS 연동은 언제 하나

POS에서 메뉴별 판매 수량을 내려받을 수 있고, 메뉴마다 재료 사용량(예: 유자차 1잔 = 유자청 30g)을 정리할 수 있다면 소비량을 추정이 아니라 계산으로 얻습니다. 예상 오차를 크게 줄이는 가장 강력한 방법이지만 준비물이 많아 3단계 이후, 조건부로 둡니다. POS 제품명을 알려 주시면 내보내기 가능 여부를 먼저 확인하겠습니다.

A.1 발주 계산 규칙 (앱에 구현된 그대로)

상황계산예
일반 품목발주 = 기준 − 현재 (0 미만이면 0)탄산수 기준 8, 현재 3 → 5개
박스 발주 품목 (1box>6)부족 개수 ÷ 6을 올림한 박스 수아이스티 기준 6, 현재 0 → 1박스
기준이 박스 단위 (2BOX)박스로 세고 박스로 발주배도라지차 기준 2박스, 현재 1박스 → 1박스
세는 단위가 박스인 품목박스 수 × 1박스 개수로 환산해 계산. 1박스 개수가 없으면 계산하지 않고 경고—
최소 발주 수량부족분이 있으면 최소 수량 이상으로—
재발주점 규칙 (유자청·청귤청)현재 < 3 이면 1박스, 아니면 0. 기준 수량은 쓰지 않음유자청 현재 2 → 1박스 / 현재 3 → 없음
미입력 품목발주 0, 발주 탭에 경고. 기준·규칙 없는 품목은 "기준 없음"으로 따로 표시원두, 우유, 라면류
직접 수정발주 탭에서 고친 수량이 우선. 재고조사 값을 다시 고치면 자동 계산으로 복귀—
