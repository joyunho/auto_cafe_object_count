이 문서를 읽는 방법

바쁘면 1장과 11장만 읽어도 결정할 수 있습니다. 5장은 "자동으로 세는 게 되나"에 대한 답이고, 6장은 "앱 말고 웹으로 직원 모두가 쓸 수 있나"에 대한 답입니다. 낯선 용어는 부록 A.3에 풀어 두었습니다.

1한 장 요약

두 질문에 대한 답

① "재고를 자동으로 셀 수 있나?" — 기계가 전부 세 주는 방법은 카페 규모에서 현실적이지 않습니다. 닫힌 박스 안과 뒷줄은 카메라도 못 봅니다. 대신 세지 않아도 되게 만듭니다. 품목마다 재발주 카드를 두어 카드가 빠진 것만 발주하고, 앱이 "지금쯤 몇 개"를 계산해 카드 누락을 잡아 주며, 자주 쓰는 10~15개만 직원이 직접 봅니다. 68개를 다 세는 일은 없어집니다.

② "앱 말고 웹으로 직원 모두가 쓸 수 있나?" — 됩니다. 카톡으로 받은 링크 하나를 열면 끝이고, 홈 화면에 추가하면 앱처럼 보입니다. 설치·가입·비용이 없습니다. 지금 부족한 것은 직원들이 같은 데이터를 보는 공유 저장소 하나이고, 그것을 붙이는 것이 1단계입니다.

앱은 이미 만들어져 있습니다(4장). 이 문서는 그것을 팀용으로 넓히고 세는 일을 줄이는 계획이며, 세 단계로 갑니다. 각 단계는 끝날 때마다 실제로 쓸 수 있는 상태입니다.

단계내용직원이 느끼는 변화소요
1단계공유 저장소 연결, 매장 링크, 입고 확인, 재발주 카드 인쇄·카드 발주 화면누가 세든 같은 화면. 발주함의 카드만 체크하면 발주 초안이 나오고, 문자는 버튼 하나로 복사.4~6 작업일
2단계예상 재고와 "확인 필요" 표시, 품목 등급별 돌아가며 세기카드가 빠졌는지 앱이 잡아 주고, 매번 세는 품목은 A등급 10~15개로 줄어든다.4~5 작업일 (기록 3~4회 뒤)
3단계핵심 품목 개봉 스티커(휴대폰을 대면 −1), 예상 오차 리포트핵심 품목은 실시간 재고. 확인 대상이 더 준다.2~3 작업일

POS 판매 자료 연동은 POS 종류를 확인한 뒤 따로 결정합니다(5.5).

"예상 재고"만으로는 부족한 이유와, 그보다 나은 방식
예상 재고는 추정이라 틀릴 수 있고, 그래서 결국 다 세게 되기 쉽습니다. 제안은 재발주 카드로 "나가는 순간"을 물리적으로 기록해 세는 일 자체를 없애고, 예상 재고는 카드가 빠졌는지 검증하는 용도로 쓰는 것입니다. 헷갈리는 품목은 항상 직접 세므로 발주 정확도는 지금보다 떨어지지 않게 하는 것이 목표입니다.

결정 요청 — ① 공유 저장소를 사장님 구글 계정으로 만들어도 되는지 ② 재발주 카드를 전 품목에 둘지 ③ 사진 인식은 빼는지 ④ POS 종류 ⑤ 시트에서 불확실했던 두 가지. 답변 양식은 11장.

2지금의 방식과 문제

지금 하는 일

  1. 월요일·목요일에 코팅된 재고조사 시트 3장을 들고 창고·선반·냉장고를 돌며 68개 품목을 셉니다.
  2. 빨간 기준 숫자(예: 유자청 8)와 남은 수량을 비교해 발주량을 머리로 정하고, 매직으로 적습니다.
  3. 시트를 사진으로 찍어 거래처(씨앤비)나 담당자에게 보냅니다. 다음 조사 때 지우고 다시 적습니다.

불편한 점

문제왜 생기나결과
매번 전부 센다지난번에 몇 개였는지, 얼마나 쓰는지 기록이 없어 매번 처음부터 셉니다.회당 20~30분, 주 2회
계산·전달 실수박스 단위(1box=6), 2BOX, "3개 미만이면 1박스" 같은 규칙을 사람이 기억해 적용합니다.과·소발주, 누락
기록이 사라진다시트를 지우고 다시 쓰므로 소비 추세, 품절 빈도를 알 수 없습니다.기준 수량을 감으로 조정
한 사람에게 몰린다시트와 규칙을 아는 사람만 할 수 있고, 다른 직원은 결과를 볼 수 없습니다.휴무·퇴사 때 공백
사진 공유의 한계손글씨 사진은 검색·집계가 안 되고, 잘못 읽히기도 합니다.거래처와 확인 왕복

시트의 규칙은 그대로 앱에 넣었습니다

빨간 숫자 = 기준 수량, (1box>6) = 1박스 6개, 배도라지차 2BOX = 박스 단위, 각주의 "유자·청귤은 3개 미만이면 1박스"는 앱 규칙으로 넣었습니다. 손글씨로 추가된 라면류와 단무지도 등록했고, 줄을 그어 지운 컵라면은 사용 안 함으로 두었습니다. 자세한 규칙은 부록 A.1, 시트만으로는 확인이 안 된 2건은 11장 5번에 있습니다.

  • 직원에게 새 습관을 최소로 요구한다. 필수 습관은 세 가지입니다. 월·목에 앱 열기, 카드 붙은 병을 꺼낼 때 카드를 발주함에 넣기, 배송이 오면 "입고 확인"을 누르고 카드를 제자리에 끼우기.
  • 설치·계정·비용 없이 시작한다. 링크와 홈 화면 추가만으로 참여합니다.

4이미 만들어진 것 (v0.1)

시트 3장을 그대로 옮긴 웹앱이 완성되어 있습니다. 지금은 각자 휴대폰에만 저장되는 개인용이고, 6장의 공유 저장소를 붙이면 그대로 팀용이 됩니다.

화면기능
재고조사68개 품목을 시트 그룹별로 표시. 입력 즉시 저장. "빈칸=기준"으로 안 센 품목을 기준값으로 채우기.
발주기준−현재, 박스 올림, 최소 발주, 재발주점 규칙 자동 적용. 수량 직접 수정 가능. 카카오톡용 발주 문자 복사·공유. 확정하면 기록으로.
기록조사·발주 이력, 품목별 하루 소비량, 자주 품절되는 품목, 기준 수량 변경 제안.
품목품목 추가·편집·숨김, 기준 수량, 1박스 개수, 발주·세는 단위, 규칙, 별칭.

검증 상태

  • 발주 계산 규칙(박스 환산·최소 발주·재발주점)과 저장·백업은 자동 검사를 거쳤고, 휴대폰 크기 화면에서 입력→발주→확정→기록→백업까지 한 바퀴 도는 것을 확인했습니다.

  • 아직 못 한 것: 홈 화면에 추가한 뒤 오프라인에서 열리는지는 실제 휴대폰에 배포한 뒤 확인합니다. 여러 휴대폰이 같은 데이터를 보는 것은 1단계에서 만듭니다.

5재고를 세지 않고 알아내는 방법

5.1 원리

재고는 마지막으로 확인한 수 + 들어온 수 − 나간 수입니다. 사진이나 센서는 "지금 상태를 다시 재는" 방식이고, 아래 방법들은 들어오고 나가는 순간을 잡거나, 애초에 셀 필요를 없애는 방식입니다. 카페 재고는 닫힌 박스 안, 앞 병에 가려진 뒷줄, 지하 창고, 생김새가 같은 병이 많아 "기계가 다 세 준다"보다 "사람이 볼 것만 골라 준다"가 현실적인 목표입니다.

5.2 후보 비교

방법어떻게세는 일이 얼마나 줄어드나준비 · 비용약점
① 재발주 카드 제안품목마다 카드를 재고 더미의 재발주점 위치에 끼워 둠. 카드 붙은 병을 꺼내면 카드를 발주함에 넣음. 발주일엔 발주함의 카드만 발주거의 전부. 병원·급식·공장이 쓰는 방식카드 68장 인쇄·코팅, 몇천 원. 앱이 QR 포함해 만들어 줌입고 때 카드를 제자리에 다시 끼워야 함. 뒤섞이는 선반은 안 맞음
② 개봉 스티커 제안선반 칸에 스티커를 붙이고, 새 병을 딸 때 휴대폰을 갖다 대면(NFC) 그 품목이 −1핵심 품목은 실시간 재고스티커 장당 300~500원, 68장 약 3만 원. 아이폰·안드로이드 기본 지원전원이 빠짐없이 대야 함. 빼먹으면 어긋남(주 2회 확인으로 보정)
③ 등급별 돌아가며 세기 제안비싸거나 잘 떨어지는 A품목만 매번, B는 격주, C(각설탕·시나몬·부탄가스·잣 등)는 월 1회. 앱이 "이번엔 이것만"을 정함회당 68개 → 약 20개없음줄이는 것이지 없애는 건 아님
④ 예상 재고 + 확인 필요 제안지난 조사값 + 입고 − 평균 소비×경과일. 발주 결정이 갈릴 수 있는 품목만 "확인 필요"카드 누락을 잡는 안전망. 카드 없이 쓰면 회당 10~15개기록 3~4회. 씨앤비 발주 내역을 받으면 첫 주부터 가능추정이라 틀릴 수 있음. 주말·행사 변동
⑤ 정기 발주로 빼기 제안소비가 일정한 품목은 씨앤비와 "매주 N개" 고정. 거래처가 선반 보고 채우는 방식이 되는지도 확인해당 품목은 조사에서 완전히 빠짐거래처 협의거래처가 응해야 함
⑥ POS 판매 × 레시피메뉴 판매량으로 재료 소비를 계산음료 재료는 추정이 아닌 계산POS 내보내기, 레시피 표준비물이 가장 많음. 폐기·서비스 소비는 못 잡음
사진 세기 있음 미검증선반 사진을 AI가 세어 줌앞줄에 보이는 병만별도 계정(API 키), 장당 50~80원가려진 것·닫힌 박스·비슷한 병. 이 계획에서는 뺌

5.3 제안하는 조합: ① 재발주 카드 + ③ 등급별 세기 + ④ 예상 재고

유자청
기준 8개 · 1박스 6개
카드 위치: 뒤에서 3번째 병
이 카드가 보이면 1박스 발주
병을 꺼낼 때 이 카드를 발주함에 넣어 주세요. 입고되면 다시 뒤에서 3번째에 끼웁니다.

재발주 카드는 시트의 규칙을 종이 한 장으로 옮긴 것입니다. 유자청은 "3개 미만이면 1박스"이므로 카드가 뒤에서 3번째 병에 붙어 있고, 그 병을 꺼내는 순간이 곧 재발주 시점입니다. 직원은 세지 않고 카드만 발주함에 넣습니다. 발주일에는 발주함의 카드를 앱에서 체크하거나 QR을 찍으면 초안이 만들어지고, 카드 68장은 앱이 인쇄용으로 만들어 줍니다.

선반에 품목별 자리가 정해져 있을 때 잘 맞습니다. 자리가 없는 품목은 ③·④로만 관리해도 됩니다.

예상 재고는 카드가 빠졌을 때(안 넣었거나 잃어버린 경우)를 잡는 안전망입니다. 발주에 필요한 판단은 기준보다 얼마나 부족한가와 재발주점을 넘었는가 두 가지뿐이라, 예상값에 오차를 붙여도 판단이 바뀌지 않으면 세지 않고, 판단이 갈리는 품목만 "확인 필요"로 표시합니다.

확인하지 않아도 되는 예 — 탄산수
기준 8. 지난 목요일 5개, 그 뒤 3개 입고. 하루에 보통 1.2개쯤 씁니다(적으면 0.9개, 많으면 1.5개). 그러면 월요일 아침 재고는 대략 3개, 어긋나도 2~4개 사이입니다. 2개든 4개든 발주는 4~6개이고 앱 초안은 5개입니다. 실제가 2개였다면 발주 후 7개로 기준보다 1개 적지만, 다음 목요일까지 쓰는 양(약 4개)보다 넉넉해 품절은 나지 않고 목요일 조사에서 다시 채워집니다. → 세지 않음, 5개 발주 초안
확인해야 하는 예 — 유자청
규칙: 3개 미만이면 1박스. 예상 3개 안팎(2~4개)인데 발주함에 카드가 없습니다. 2개면 발주, 3개 이상이면 발주 안 함 — 결정이 갈리고 카드도 없으니 → "확인 필요" 표시. 직원은 이 품목만 실제로 봅니다.

정확도를 올리는 장치

  • 씨앤비 발주 내역으로 미리 학습. 지난 3~6개월 발주 내역을 거래처에 요청해 넣으면 첫 주부터 예상 재고가 작동합니다.
  • 요일 구간별 소비 속도. 월→목(평일 3일)과 목→월(주말 포함 4일)을 따로 계산합니다. 지금처럼 월·목에 조사만 하면 됩니다.
  • 입고 확인(1단계). 발주량이 그대로 왔다고 가정하지 않고 배송 때 실제 수량을 반영합니다.
  • 오차 자기 점검. 실측 때마다 예상값과의 차이를 기록해, 오차가 커진 품목은 "확인 필요"에 올리고 작은 품목은 뺍니다.
  • 핵심 품목 개봉 스티커(3단계, 선택). 유자청·청귤청·원두·우유·아이스크림처럼 비싸거나 품절이 치명적인 5~6개만 ②를 적용하면 실시간 재고가 됩니다.

5.4 세는 품목이 줄어드는 시간표

시기하는 일발주일에 세는 품목
1주링크 배포, 앱으로 68개 전 품목 입력(시트와 병행). 카드 인쇄·배치. 씨앤비에 발주 내역 요청.68개
2주시트 없이 앱만. 발주함 카드 체크로 발주 초안. 입고 확인 시작. A품목만 실측.A품목 10~15개 + 카드
3~4주예상 재고 켜기(발주 내역으로 시작). 앱이 값을 미리 채워 두므로 "세기"가 아니라 "틀린 것만 고치기". 예상값이 얼마나 맞는지 측정.A품목 + "확인 필요"
5주~B·C품목은 돌아가며 세기. 핵심 품목 개봉 스티커(선택). 기준 수량 제안 적용.10~15개

정확한 품목 수는 매장의 소비 변동에 달려 있어 도입 후 측정합니다. 8·10·11장도 이 시간표를 씁니다.

5.5 POS 연동은 언제 하나

POS에서 메뉴별 판매 수량을 내려받을 수 있고 메뉴마다 재료 사용량(예: 유자차 1잔 = 유자청 30g)을 정리할 수 있다면, 소비량을 추정이 아니라 계산으로 얻습니다. 준비물이 많아 조건부로 두고, POS 제품명을 받으면 내보내기 가능 여부부터 확인합니다.

6.2 동작 방식

  • 매장 전용 링크. 긴 무작위 주소가 붙은 링크를 카톡으로 받으면 그 매장 데이터에 바로 연결됩니다. 로그인·가입 없음.
  • 품목별 병합. 재고조사 값은 품목 단위로 저장되어, A가 청 종류를 세고 B가 브런치를 세도 서로 덮어쓰지 않습니다.
  • 오프라인. 지하 창고에서 신호가 없어도 입력은 저장되고, 신호가 잡히면 자동으로 올라갑니다. 예상 재고와 발주 초안은 앱을 열 때 휴대폰 안에서 계산됩니다(서버 없음).
  • 담당자 표시와 백업. 기기마다 이름을 한 번 적어 두면 기록에 "누가 언제"가 남고, 설정에서 언제든 백업 파일로 내려받습니다.

6.3 보안 수준 — 솔직하게

링크를 아는 사람은 누구나 보고 수정할 수 있습니다. 링크는 길고 무작위라 추측은 어렵지만, 퇴사자가 링크를 갖고 있으면 매장 코드를 새로 발급해 옮깁니다(직원 전원이 새 링크를 다시 추가). 카페 재고 정보의 민감도에서는 보통 충분하며, 필요하면 직원별 4자리 비밀번호를 추가할 수 있습니다.

개발은 이 제안대로 진행하면 1~3단계 합쳐 약 10~14 작업일입니다. 유지관리는 품목·기준 변경을 직원이 앱에서 직접 하고, 코드 변경이 필요한 일은 드뭅니다.

10위험과 대응

위험가능성대응
직원이 앱을 안 쓰고 시트로 돌아감중첫 주는 시트와 병행, 2주째부터 앱만. 앱이 시트보다 빠르다는 것을 발주 시간으로 보여 줌. 필수 습관을 3개(월·목 열기, 카드 넣기, 입고 확인)로 제한.
카드를 안 넣거나 잃어버림중예상 재고가 "확인 필요"로 잡아 줌(3주째부터). 그 전에는 A품목 실측이 잡아 줌. 카드는 앱에서 1장씩 재인쇄.
예상 재고가 틀려 품절·과발주중결정이 갈리는 품목은 항상 실측. 오차가 커진 품목은 자동으로 확인 대상에 복귀. 직접 센 값이 항상 우선. 첫 달은 전 품목을 보는 기간(5.4).
입고 확인을 빠뜨림중발주 후 예상 배송일이 지나면 앱을 열었을 때 위쪽에 "입고 확인 안 됨" 표시(휴대폰 알림은 아님). 미확인 시 발주량 전량 입고로 가정하고 다음 실측에서 보정.
링크 유출낮매장 코드 재발급으로 즉시 차단(직원은 새 링크 재추가). 필요 시 직원별 4자리 비밀번호 추가.
저장소 장애·데이터 유실낮휴대폰에 마지막 상태가 남아 오프라인으로 계속 사용. 주 1회 백업 파일 내려받기 안내.
시트 판독 오류(기준 수량 등)낮68개 품목 전부 두 번 독립 판독 후 대조. 남은 불확실 2건은 11장에서 확인 요청.

11결정이 필요한 것

아래 다섯 가지가 정해지면 1단계를 바로 시작합니다. 기본안(굵게)을 그대로 택하셔도 됩니다.

1
공유 저장소를 사장님 구글 계정으로 만들어도 될까요?
기본안: 네, 사장님 구글 계정(구글이 운영하는 무료 저장소 Firebase). 만드는 데 약 10분, 카드는 필요 없습니다. 화면 순서를 캡처로 안내해 드리고, 원하시면 제가 만든 뒤 사장님 계정을 소유자로 추가해 드릴 수도 있습니다. 스프레드시트에서도 보고 싶으면 시트 연동으로 대체 가능.
2
재발주 카드를 전 품목에 둘까요, 자리가 정해진 품목에만 둘까요?
기본안: 전 품목(68장). 선반에 품목별 자리가 대체로 정해져 있다면 전 품목이 맞고, 뒤섞이는 선반이 많으면 자리가 있는 품목만 카드로 하고 나머지는 예상 재고와 등급별 세기로 관리합니다. 매장 선반 상태를 알려 주시면 정하기 쉽습니다. 개봉 스티커를 붙일 핵심 품목(유자청·청귤청·원두·우유·아이스크림 정도)은 3단계 전에 따로 여쭙겠습니다.
3
사진 인식은 이 계획에서 빼도 될까요?
기본안: 뺍니다. 앱에 기능은 남겨 두되 축으로 쓰지 않습니다. 쓰기로 하면 사진 인식 회사(Anthropic)에 계정을 만들고 해외 결제 카드를 등록해야 하고(월 2,000~3,000원), 실제 매장 사진으로 정확도를 먼저 재 봐야 합니다.
4
매장 POS는 어떤 제품인가요? 판매 내역을 내려받을 수 있나요?
제품명만 알려 주시면 내보내기 가능 여부와 레시피 연동 난이도를 확인해 조건부 단계를 확정합니다. 아울러 씨앤비에 지난 3~6개월 발주 내역을 요청해 주시면 예상 재고를 첫 주부터 쓸 수 있습니다.
5
시트에서 불확실했던 두 가지
① 시트 1 "레몬"(주스 칸)과 시트 2 "레몬"(시럽 칸)은 실제로 다른 품목인가요? 각각 무엇인가요? ② 각주 "유자, 청귤 최소발주 6○○"의 단위(단지/상자)는 무엇인가요? 현재는 1박스=6개로 두었습니다.
카톡으로 이렇게만 답해 주시면 됩니다
  1. 저장소: 기본안 / 시트 연동 / 대신 만들어 주세요
  2. 카드: 전 품목 / 자리 있는 품목만 (선반 상태: ______)
  3. 사진 인식: 뺌 / 나중에 시험
  4. POS 제품명: ______ / 씨앤비 발주 내역: 요청함 / 어려움
  5. 레몬(주스)=______, 레몬(시럽)=______ / 각주 "6" 단위=______

결정 안 된 항목은 "기본안대로"라고만 알려 주셔도 됩니다.

결정 후 1~2주 안에 일어나는 일
구글 저장소 설정값 전달 → 공유 저장소 연동·카드 화면·배포(4~6 작업일) → 매장 링크와 카드 PDF 발급 → 직원에게 카톡으로 링크 전송, 카드 인쇄·배치 → 다음 월요일 재고조사부터 앱으로.

A.1 발주 계산 규칙 (앱에 구현된 그대로)

상황계산예
일반 품목발주 = 기준 − 현재 (0 미만이면 0)탄산수 기준 8, 현재 3 → 5개
박스 발주 품목 (1box>6)부족 개수 ÷ 6을 올림한 박스 수아이스티 기준 6, 현재 0 → 1박스
기준이 박스 단위 (2BOX)박스로 세고 박스로 발주배도라지차 기준 2박스, 현재 1박스 → 1박스
세는 단위가 박스인 품목박스 수 × 1박스 개수로 환산해 계산. 1박스 개수가 없으면 계산하지 않고 경고—
최소 발주 수량부족분이 있으면 최소 수량 이상으로—
재발주점 규칙 (유자청·청귤청)현재 < 3 이면 1박스, 아니면 0. 기준 수량은 쓰지 않음유자청 현재 2 → 1박스 / 현재 3 → 없음
미입력 품목발주 0, 발주 탭에 경고. 기준·규칙 없는 품목은 "기준 없음"으로 따로 표시원두, 우유, 라면류
직접 수정발주 탭에서 고친 수량이 우선. 재고조사 값을 다시 고치면 자동 계산으로 복귀—
재발주 카드 (제안)카드 위치 = 재발주점(규칙이 없으면 기준의 절반, 최소 1). 카드가 발주함에 있으면 그 품목을 기준까지 채우는 수량으로 초안딸기청 기준 8 → 카드는 뒤에서 4번째
